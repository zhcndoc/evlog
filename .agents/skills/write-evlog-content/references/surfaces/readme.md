# 表面：README

仓库根目录中的 `README.md` 是指向 `packages/evlog/README.md` 的**符号链接**。编辑包文件。通过根路径编辑符号链接目标实际上是同一个文件，但在 PR 中引用根路径会掩盖发生了哪些更改。

## 它要为读者提供什么

某个正在 npm 或 GitHub 上决定是否在三十秒内继续阅读的人。它按顺序回答三个问题：

1. 这是什么，用一句经得起替换测试的话说明。
2. 代码是什么样的，用能运行的最小完整示例说明。
3. 接下来去哪里：安装、文档、框架列表。

其他所有内容都应该是链接。不断扩展成文档的 README，是没人为其进行版本管理的文档。

## 这里最关键的规则

- **U-04** 最棘手：徽章和单行声明是仓库中最难验证的文字。
- 框架列表和适配器列表会悄无声息地过时。每次检查 README 内容时，都要对照 `packages/evlog/package.json#exports` 检查这两者。
- 由 automd（`.github/automd.json`）生成的章节应重新生成，而不是手动编辑。编辑某个区块前，先检查标记。
