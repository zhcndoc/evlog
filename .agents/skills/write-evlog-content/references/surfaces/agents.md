# Surface：AGENTS.md

三个文件，特意嵌套：根目录下的 `AGENTS.md`、`apps/docs/AGENTS.md`、`apps/evi/AGENTS.md`。根目录文件通过符号链接关联到 `CLAUDE.md`，因此对前者的编辑也会同时反映到后者。嵌套文件只记录其所在目录适用的内容，不记录任何属于根目录的内容。

## 它对读者的职责

一个即将修改此仓库、且尚未阅读其他内容的代理。它应以一种即使上下文中只有这一份内容也能继续有效的形式，提供命令、约定、完成定义以及边界。

根目录文件自称是活文档。这就是本次检查所执行的契约：不再存在的命令、已经移动的路径、不真实存在的工作流，都是严重问题，而不是风格问题。

## 这里真正起作用的规则

- **M-07** 高于一切。这个文件最有可能描述上个季度的仓库。
- **M-04**：Boundaries 部分是文件有效的原因。将“永远不要”弱化为“尽量避免”的重写会改变行为。
- **M-09**：流程和边界交给维护者。检查确认过的标点、失效链接以及过时路径可以直接修复。
- **U-14** 在这里同样适用。这些文件是关于如何撰写文档的散文，而且它们的阅读频率高于任何文档页面。

## 内容检查会检查什么

- Commands 块中的每条命令都存在于相应的 `package.json` 中。
- layout 块中的每条路径都存在于磁盘上。
- `.agents/skills/` 中列出的每项 skill 都确实存在，并且其中的每项 skill 都被列出。
- 增长。根目录文件本身的指示是，修正应当只有几行，而不是一次重写。一个每月新增一个章节的文件就是问题所在。

## 它永远不会变成什么

文档。当这里的某个章节是在解释某件事，而不是做出决定时，该章节就应该归入文档，文件中保留一个链接。这是所有长期存在的代理指令文件都会出现的失败模式，而根目录文件已经有 1600 个词。
