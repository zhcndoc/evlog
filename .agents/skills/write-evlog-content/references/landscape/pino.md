# pino

检查时间：2026-08-14 · 来源：https://getpino.io

默认比较对象。大多数来到 evlog 的读者要么使用 pino，要么曾考虑过使用它，因此这是最常用的档案。

## 它的功能

- Node 的 JSON 日志记录器。级别为数字（`trace` 10 到 `fatal` 60），除非格式化程序对其进行更改，否则级别会以数字形式写入
- `logger.child(bindings)` 返回一个携带额外字段的日志记录器。绑定会在创建时固定
- 传输（`pino.transport`、`pino/file`、`pino-pretty`）通过 `thread-stream` 在线程中运行，因此序列化仍在主线程上进行，而写入操作不在主线程上进行
- 内置脱敏功能：`redact: ['req.headers.authorization']`，支持路径语法，可进行遮盖或移除
- 按键配置序列化器（`serializers: { err: pino.stdSerializers.err }`）
- `pino-http` 是请求日志记录器，并在响应时输出日志
- 低开销是该项目声明的设计目标，其基准测试结果已发布在仓库中

## evlog 的不同之处

- pino 每次调用都会写入一行。evlog 会在请求期间累积字段，并在最后输出一个事件，包括处理程序抛出异常的情况
- `child()` 绑定只设置一次。`log.fork()` 会分支出已累积的上下文，并且可以在不影响父上下文的情况下丢弃
- pino 的排出器是由用户组装的传输。evlog 提供适配器和管道，用于批处理、重试，并隔离发生故障的传输

## 我们绝不能说什么

- 不能说 pino 很慢。它并不慢，它就是速度最快的那个，进行基准测试的读者将在一分钟内发现这一点。任何提到 pino 的性能描述都必须带有数字及其来源，否则就不能发布
- 不能说 pino 没有脱敏、序列化器或请求日志记录功能。三者它都有
- 不能说 pino 无法处理宽事件。没有任何东西阻止用户累积一个对象并一次性记录它；evlog 提供的是累积过程、请求生命周期以及错误路径
