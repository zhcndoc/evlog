# consola

检查日期：2026-08-14 · 来源：https://github.com/unjs/consola

consola 是 evlog 的目标受众已经安装的日志记录器。Nuxt 用户会先接触到它，然后才会接触到他们选择的其他日志记录器，因此比较必须围绕适用范围，而不是质量展开。

## 它能做什么

- 面向 Node、浏览器和 workers 的控制台日志记录器，属于与 Nitro 和 Nuxt 相同的 unjs 生态系统
- 报告器负责渲染输出。内置三种：`fancy`、`basic` 和 `browser`。内置版本没有 JSON 报告器；结构化输出需要使用自定义报告器
- 自定义报告器是一个带有 `log(logObj, ctx)` 方法的对象，因此它负责传递日志，并可以将其序列化、缓冲、批处理或转发到任意位置
- `consola.withTag('name')` 可以限定输出范围，`consola.wrapConsole()` 可以捕获 `console.*`
- 日志传递并非无条件进行。`pauseLogs()` 会将调用排队，直到 `resumeLogs()` 清空队列；重复的相同日志会被限流，而不是重复输出
- 提供适用于 CLI 的提示辅助工具、旋转指示器和框输出
- 日志级别为数字，并且可以全局设置

## evlog 的不同之处

- consola 的基本单位是调用。日志记录运行时，调用会到达其报告器；`pauseLogs()` 挂起调用时，调用会在队列中等待；如果是重复日志，则会被丢弃。evlog 的基本单位是工作：它会在一次请求或一个任务期间累积字段，并在请求或任务结束时发出一个事件，即使处理程序抛出异常也一样
- consola 的排队是一个暂停开关，而不是一种策略。evlog 内置批处理、采样、重试和排空适配器，在它们之间进行选择属于配置的一部分。在 consola 中，这需要由你编写并维护一个自定义报告器
- consola 没有请求生命周期，也没有累积的上下文。这是读者最先感受到的差异

## 我们绝不能这样说

- 不能说 consola 无法进行结构化输出。它没有内置 JSON 报告器，而自定义报告器只需几行代码即可实现。诚实的说法应当围绕内置内容，而不是可能实现的功能
- 不能说 consola 总是立即写入。`pauseLogs()` 会将日志排队，重复日志会被限流，而自定义报告器完全负责日志传递。要么明确指出具体机制，要么不要在句子中提及日志传递
- 不能说它只适用于 CLI。它运行在 Nitro 和浏览器中，也有很多应用在生产环境中使用它
- 任何读起来像是在批评 consola 没有成为遥测管道的话都不能说。它本来就不是要成为遥测管道，诚实的说法应当围绕读者的需求转向了哪里，而不是 consola 缺少什么
