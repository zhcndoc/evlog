使用 evlog 客户端日志将浏览器日志发送到我的服务器。

- 检测我的框架（Nuxt、Next.js、SvelteKit 等），并选择匹配的客户端入口
- 在应用启动时调用 initLog({ service: 'web' }) 一次。Nuxt 模块的客户端插件已从 nuxt.config 调用 initLog；不要重复调用
- 在组件、composables 和事件处理器中使用 log.info / log.warn / log.error
- 登录后使用 setIdentity({ userId, email }) 设置用户身份，退出登录时调用 clearIdentity()
- 如需发送每条事件，请启用传输。Nuxt：在 nuxt.config.ts 中设置 evlog.transport.enabled，使模块注册摄取路由。每条事件都会通过 fetch keepalive，以单个 JSON 对象 POST 到 transport.endpoint（默认值为 /api/_evlog/ingest）。失败会静默忽略。这里没有批处理缓冲区，也不会在页面隐藏时刷新
- 如需批处理（默认每 2 秒最多 25 条）、重试以及在 visibilitychange 变为 hidden 时刷新，请对批次端点使用来自 evlog/http 的 createHttpLogDrain。页面隐藏时通过 sendBeacon 发送，其他时候使用 fetch keepalive。不要将这个 drain 指向内置摄取端点
- 对于 Nuxt 摄取，服务器会先对事件脱敏，再使用 source: 'client' 运行 drain 管道

文档：https://www.evlog.dev/use-cases/client-logging
HTTP transport：https://www.evlog.dev/extend/drain-pipeline

## 快速开始

evlog 提供了一个可在任何浏览器环境中使用的客户端日志 API：

::framework-tabs
```typescript [Nuxt] app/plugins/app-init.client.ts
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('app:created', () => {
    log.info({ action: 'app_init', path: window.location.pathname })
  })
})
```
```typescript [app/providers.tsx (React / Next.js)]
'use client'
import { useEffect } from 'react'
import { initLog, log } from 'evlog/client'

export function LogProvider({ children }: { children: React.ReactNode }) {
  useEffect(() => {
    initLog({ service: 'web' })
    log.info({ action: 'app_init', path: window.location.pathname })
  }, [])

  return <>{children}</>
}
```
```typescript [src/app.ts (任意前端)]
import { initLog, log } from 'evlog/client'

initLog({ service: 'web' })
log.info({ action: 'app_init', path: window.location.pathname })
```
::

在 Nuxt 中，模块的客户端插件已经使用 `nuxt.config.ts` 里的 `evlog` 选项调用 `evlog/client` 的 `initLog`。再次调用 `initLog()` 会将包括 `service`、`pretty`、`minLevel` 和 `transport` 在内的所有选项重置为默认值。客户端服务名称固定为 `'client'`。

`log` 对象可以在你的客户端代码中任何地方使用：组件、composables、事件处理器。

## 最低级别（`minLevel`）

使用 `initLog({ minLevel: 'warn' })` 来保持浏览器控制台安静（仅显示警告和错误）。严重性顺序为：`trace` < `debug` < `info` < `warn` < `error` < `fatal`。默认值为 `'debug'`（输出所有级别）。

如果需要**无需重新加载即可切换调试模式**，可以在用户选择开启或关闭详细日志时，从 `evlog/client` 调用 `setMinLevel('debug')` 或 `setMinLevel('warn')`。

`minLevel` 同时适用于控制台输出和[向服务器发送日志](#sending-logs-to-the-server) 的有效载荷。

## 两种调用方式

`log` API 根据上下文接受两种形式。

### 对象形式（结构化上下文）

传递一个对象以捕获结构化数据，就像服务器端的 `log.set()` 一样：

```typescript [pages/products.vue]
log.info({ action: 'page_view', path: '/products', referrer: document.referrer })
```

```bash [浏览器控制台]
[web] info  { action: 'page_view', path: '/products', referrer: 'https://google.com' }
```

### 标签 + 消息形式（快速日志）

传递标签和消息以输出快速、可读的日志：

```typescript [composables/useAuth.ts]
log.info('auth', 'User logged in')
```

```bash [浏览器控制台]
[auth] User logged in
```

消息支持 printf 风格的插值，与[服务端日志的格式化方式](/learn/simple-logging#interpolate-values-into-the-message)相同。当消息包含 `%s`、`%d` 或 `%j` 且后面有额外参数时，evlog 会在写入控制台前对其进行格式化：

```typescript [composables/useCart.ts]
log.info('cart', 'Item %s added, cart total %d', 'SKU-42', 9999)
```

```bash [Browser console]
[cart] Item SKU-42 added, cart total 9999
```

### 可用的级别

两种形式均支持六个级别：`log.fatal()`、`log.info()`、`log.warn()`、`log.error()`、`log.debug()` 和 `log.trace()`。

在浏览器中，`log.debug()` 会通过 `console.log`（而不是 `console.debug`）输出，以便在默认的 DevTools **Info** 过滤器下仍可见；结构化事件仍然包含 `level: 'debug'`。

## 浏览器事件中的错误

浏览器事件中的错误会像服务器上的错误一样序列化。`log.error(err)` 或对象形式事件（例如 `log.error({ action: 'checkout', error })`）中的 `Error`，都会连同 `name`、`message`、`stack` 和自身字段一起记录，而不是 `{}`。规则见[错误如何被记录](/learn/structured-errors#how-errors-are-logged)。

默认设置 `pretty: true` 时，浏览器控制台会收到真实的 `Error`，因此 DevTools 中可以展开查看错误对象。JSON 控制台输出和 transport 收到的则是序列化形式。

## 添加日志所属用户


使用 `setIdentity()` 跟踪生成日志的用户：

```typescript [composables/useAuth.ts]
import { setIdentity, clearIdentity, log } from 'evlog/client'

// 登录后
setIdentity({ userId: 'usr_123', plan: 'pro' })

log.info({ action: 'dashboard_view' })
// → { userId: 'usr_123', plan: 'pro', action: 'dashboard_view', ... }

// 注销后
clearIdentity()
```

身份字段会在清除之前自动合并到每个日志事件中。这使得你可以在可观测性工具中将浏览器事件关联到特定用户。

## 配置

`initLog()` 接受以下选项：

| 选项 | 默认值 | 描述 |
|------|--------|------|
| `enabled` | `true` | 启用或禁用所有客户端日志记录 |
| `console` | `true` | 输出日志到浏览器控制台 |
| `pretty` | `true`（Nuxt 中为 `import.meta.dev`） | 使用带颜色的格式化控制台输出 |
| `minLevel` | `'debug'` | 最低严重级别：`trace` < `debug` < `info` < `warn` < `error` < `fatal` |
| `service` | `'client'` | 每个日志事件中包含的服务名称 |
| `transport` | - | 将日志发送到服务器端点（参见下文） |

```typescript [src/app.ts]
import { initLog } from 'evlog/client'

initLog({
  service: 'web',
  transport: {
    enabled: true,
    endpoint: '/api/_evlog/ingest', // 默认端点
  },
})
```

::callout{icon="i-lucide-info" color="info"}
`enabled` 和 `console` 默认值为 `true`。直接调用 `initLog()` 时，`pretty` 默认值为 `true`；Nuxt 模块插件调用时，默认值为 `import.meta.dev`。
::

## 向服务器发送日志

默认情况下，客户端日志只会显示在浏览器控制台中。若要持久化存储，有两种选择：

### 使用内置传输发送日志

内置传输是最简单的选项，适合低流量应用。它会为每条日志通过 `fetch` 和 `keepalive: true` POST 一个 JSON 事件。这里没有批处理缓冲区，因此页面隐藏时不会刷新，POST 失败也会被忽略。

::framework-tabs
```typescript [Nuxt] nuxt.config.ts
export default defineNuxtConfig({
  modules: ['evlog/nuxt'],
  evlog: {
    transport: {
      enabled: true,
      endpoint: '/api/_evlog/ingest',
    },
  },
})
```
```tsx [Next.js] app/layout.tsx
import { EvlogProvider } from 'evlog/next/client'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <EvlogProvider service="web" transport={{ enabled: true, endpoint: '/api/_evlog/ingest' }}>
          {children}
        </EvlogProvider>
      </body>
    </html>
  )
}
```
```typescript [src/app.ts (任意前端)]
import { initLog } from 'evlog/client'

initLog({
  service: 'web',
  transport: {
    enabled: true,
    endpoint: '/api/_evlog/ingest',
  },
})
```
::

Nuxt 模块会注册该摄取路由和一个客户端插件，后者会从同一配置调用 `initLog`。只在客户端的 `initLog()` 调用中启用传输并不会注册路由，这些 POST 请求会静默失败。其他框架需要创建一个接收单个 JSON 事件的 POST 端点。内置传输发送的是单个对象（`timestamp`、`level`、`service` 和已记录的字段），不是数组：

```typescript [Next.js] app/api/_evlog/ingest/route.ts
export async function POST(request: Request) {
  const body = await request.json()
  if (body === null || typeof body !== 'object' || Array.isArray(body)) {
    return Response.json({ error: 'expected one event object' }, { status: 400 })
  }
  return new Response(null, { status: 204 })
}
```

::callout{icon="i-lucide-info" color="info"}
内置摄取端点没有身份验证：Nuxt 端点会拒绝来自其他源的请求，可以拦截其他网站，但无法拦截脚本。请将客户端事件视为不可信输入，并在流量入口处（平台防火墙或中间件）限制该路由的请求速率，做法可参考[遥测摄取](/use-cases/telemetry/ingest)。
::

### HTTP 接收器管道

对于更高流量，或需要批处理、重试和在页面隐藏时刷新的场景，请将 `evlog/http` 中的 `createHttpLogDrain` 与 `evlog` 中的 `log` 搭配使用。它使用的 logger 与 `evlog/client` 不同：`initLog` 事件、`setIdentity` 和客户端 `minLevel` 不会经过此 drain。它适用于任何前端，不依赖具体框架。

HTTP drain 会：
- **批处理**事件（默认每 2 秒最多 25 条）
- **重试**失败的发送，并使用指数退避
- 在 `visibilitychange` 变为 `hidden`（切换标签页、导航或关闭页面）时，通过 `sendBeacon` **刷新**缓冲事件

::callout{icon="i-lucide-triangle-alert" color="warning"}
对象形式的事件会进入 drain。当 `pretty` 开启（浏览器没有 `process` 全局变量时，`isDev()` 默认返回 `true`）且 `silent` 关闭时，带标签的 `log.info('tag', 'msg')` 调用只会打印，不会进入 drain。请使用对象形式事件，或在 `initLogger` 中设置 `pretty: false`。`useBeacon` 属于 `drain` 选项（如果端点需要 `Authorization` 标头，则设置 `drain: { endpoint, useBeacon: false }`），因为 `sendBeacon` 不会发送 `headers`。请求正文是 JSON 数组，因此不要将此 drain 指向内置摄取端点。请在配置的路径创建 POST handler（Nuxt 示例中的 `/api/logs` 是需要你自行添加的路由）。参见[服务器端点](/extend/drain-pipeline#server-endpoint)。
::

::framework-tabs
```typescript [Nuxt] app/plugins/logger.client.ts
import { initLogger, log } from 'evlog'
import { createHttpLogDrain } from 'evlog/http'

export default defineNuxtPlugin(() => {
  const drain = createHttpLogDrain({
    drain: { endpoint: '/api/logs' },
    pipeline: {
      batch: { size: 25, intervalMs: 2000 },
      retry: { maxAttempts: 2 },
    },
  })

  initLogger({ drain })
  log.info({ action: 'app_init' })
})
```
```typescript [src/app.ts (任意前端)]
import { initLogger, log } from 'evlog'
import { createHttpLogDrain } from 'evlog/http'

const drain = createHttpLogDrain({
  drain: { endpoint: 'https://logs.example.com/v1/ingest' },
  pipeline: {
    batch: { size: 25, intervalMs: 2000 },
    retry: { maxAttempts: 2 },
  },
})

initLogger({ drain })
log.info({ action: 'app_init' })
```
::

## 常见问题

::accordion{type="single"}
  ::accordion-item{label="在浏览器中应该记录什么？"}
  记录操作、路由和结果：页面浏览可用 `log.info({ action: 'page_view', path })`，捕获到错误时可用 `log.error(err)`。登录后用 `setIdentity({ userId })` 关联用户，退出登录时调用 `clearIdentity()`。不要记录表单值、令牌或完整请求正文。
  ::
  ::accordion-item{label="如何将前端日志发送到服务器？"}
  启用内置传输后，每条事件都会作为一个 JSON 对象 POST 到 `/api/_evlog/ingest`（在 Nuxt 中设置 `evlog.transport.enabled` 后，该路由会自动注册）。如需批处理、重试和在标签页隐藏时刷新，请使用 HTTP drain。两种传输的约定见[将日志发送到服务器](#sending-logs-to-the-server)。
  ::
  ::accordion-item{label="如何避免前端日志包含 PII 或产生过多噪声？"}
  将 `minLevel` 提高到 `'warn'`（或用 `setMinLevel` 切换），这样 debug 噪声就不会进入控制台或传输内容。将 ID 放在 `setIdentity` 中；除非你有意保存电子邮件，否则不要记录它。不要把密钥放进事件：浏览器仍会打印你记录的内容，POST 正文也会包含它。Nuxt 摄取随后会根据服务器端的[脱敏](/learn/redaction)配置处理事件。
  ::
::
