让每个请求都产生**一个结构化 JSON 事件**，也就是一个*宽事件*，而不是一串日志行。本指南会在大约两分钟内带你完成 Node.js 服务器的接入。

## 30 秒版本

::code-group
```typescript [Before: 5 log lines]
console.log('checkout started', { requestId })
console.log('user loaded', { userId: 'u_42' })
console.log('cart loaded', { items: 3, total: 2999 })
console.log('charging card', { provider: 'stripe' })
console.log('checkout done', { status: 200, ms: 182 })
```
```typescript [After: 1 wide event]
log.set({ user: { id: 'u_42' } })
log.set({ cart: { items: 3, total: 2999 } })
log.set({ payment: { provider: 'stripe' } })
```
::

处理器调用 `log.set()`。evlog 会添加方法、路径、状态、耗时和请求 ID，并在响应发送时写入一个事件：

```json [Output]
{
  "level": "info",
  "method": "POST",
  "path": "/checkout",
  "status": 200,
  "durationMs": 182,
  "requestId": "4f1c…",
  "user": { "id": "u_42" },
  "cart": { "items": 3, "total": 2999 },
  "payment": { "provider": "stripe" }
}
```

请求失败时，你只需读取一条记录，而不是搜索五条日志；每个字段都可以查询：`payment.provider = 'stripe' AND status >= 500`。

## 为什么使用宽事件

::wide-event-collapse
::

| | 多行日志 | 一个宽事件 |
| --- | --- | --- |
| 每个请求的记录数 | 每次日志调用一条 | 最后发出一条 |
| 上下文 | 每行重复，或在某些行中缺失 | 收集一次，与结果放在一起 |
| 调试失败 | 找到请求 ID 对应的每一行，再重建过程 | 读取一个事件：输入、结果、错误和耗时 |
| 数量 | 随调用次数增长 | 每个操作固定一条，再通过[采样](/learn/sampling)减少 |

对于请求之外的内容（例如启动消息），仍然可以使用全局 `log` API 写入单独记录（[简单日志](/learn/simple-logging)）。[宽事件](/learn/wide-events)介绍了各自的适用场景。

## 记录你的第一个宽事件

随着处理器获取信息，使用 `log.set()` 添加上下文。嵌套对象会合并，因此可以分两步补充 `payment`。使用框架集成时，方法、路径、状态、耗时和请求 ID 会自动记录，响应结束时发出事件。

::framework-tabs
```typescript [Standalone] src/server.ts
import { randomUUID } from 'node:crypto'
import { createServer } from 'node:http'
import { createRequestLogger, initLogger, toLoggerConfig } from 'evlog'
import config from '../evlog.config'

initLogger(toLoggerConfig(config))

createServer((req, res) => {
  const log = createRequestLogger({ method: req.method, path: new URL(req.url ?? '/', 'http://localhost').pathname, requestId: randomUUID() })

  // Without a framework, you emit the event yourself: once, after the response is sent
  let emitted = false
  const emit = () => {
    if (emitted) return
    emitted = true
    log.emit({ status: res.statusCode })
  }
  res.once('finish', emit)
  res.once('close', emit)

  log.set({ orderId: 'order-123', payment: { amount: 2999, currency: 'EUR' } })
  log.set({ payment: { chargeId: 'ch_123' }, outcome: 'paid' })
  res.statusCode = 200
  res.end(JSON.stringify({ orderId: 'order-123' }))
}).listen(3000)
```

```typescript [AWS Lambda] src/handler.ts
export async function handler(event: APIGatewayProxyEventV2) {
  const { method, path } = event.requestContext.http
  const log = createRequestLogger({ method, path, requestId: event.requestContext.requestId })
  let statusCode = 500
  try {
    log.set({ orderId: 'order-123', payment: { amount: 2999, currency: 'EUR' } })
    log.set({ payment: { chargeId: 'ch_123' }, outcome: 'paid' })
    statusCode = 200
    return { statusCode, body: JSON.stringify({ orderId: 'order-123' }) }
  } finally {
    // Lambda has no response lifecycle to hook: emit before the handler returns
    log.emit({ status: statusCode })
  }
}
```

## 能自我说明的错误

::structured-error-context
::

`createError()` 为错误提供 `status`、`why` 和 `fix`。evlog 会将它们与失败前设置的上下文一起记录到请求事件中，`parseError()` 再读取它们来构建 HTTP 响应。

## 将日志发送到某处

::drain-fan-out
::

本地环境中，事件会打印到终端。生产环境中，**drain** 会将事件发送到后端，而且无需修改任何处理器。将它添加到配置文件后，本页面的每个集成都能使用它：

```typescript [evlog.config.ts] {6}
import { defineEvlog } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

export default defineEvlog({
  service: 'checkout',
  drain: createAxiomDrain(), // reads AXIOM_API_KEY and AXIOM_DATASET
})
```

Axiom 只是其中一个选项。Datadog、Sentry、PostHog、Better Stack、Loki、ClickHouse、OTLP 和文件系统都在[适配器概览](/integrate/adapters/overview)中。文件中的 `enrich` 函数会为每个事件添加字段，例如用户代理或部署版本（[Enricher](/use-cases/enrichers)）。

::collapsible{open-text="深入了解：" close-text="隐藏：" name="batching and flushing"}
管道会批处理事件，并重试失败的发送。进程退出前必须 flush 已缓冲的事件，这对脚本、worker 和无服务器函数尤其重要：

```typescript [evlog.config.ts] {6-7}
import type { DrainContext } from 'evlog'
import { defineEvlog } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'
import { createDrainPipeline } from 'evlog/pipeline'

const pipeline = createDrainPipeline<DrainContext>({ batch: { size: 50 } })
export const drain = pipeline(createAxiomDrain())

export default defineEvlog({ service: 'checkout', drain })
```

```typescript [src/shutdown.ts] {9}
import type { Server } from 'node:http'
import { drain } from '../evlog.config'

// Stop accepting connections, let in-flight requests finish, then flush.
// Node exits on its own once nothing is left to do.
export function flushOnShutdown(server: Server) {
  process.once('SIGTERM', () => {
    server.close(async () => {
      await drain.flush()
    })
  })
}
```

批处理大小、间隔和重试策略请参见 [Drain Pipeline](/extend/drain-pipeline)。
::

## 生产环境检查清单

- **按结果采样。**保留一部分成功的 `info` 事件，并使用 `keep` 规则始终保留错误和慢请求（[采样](/learn/sampling)）。

  ```typescript [evlog.config.ts]
  import { defineEvlog } from 'evlog'

  export default defineEvlog({
    service: 'checkout',
    sampling: { rates: { info: 10 }, keep: [{ status: 400 }, { duration: 1000 }] },
  })
  ```
- **发送前脱敏。**生产环境默认启用脱敏。为领域特有的字段添加路径（[脱敏](/learn/redaction)）。
- **退出时 flush。**脚本、worker 和无服务器函数必须在进程停止前等待待发送内容完成交付（[独立 TypeScript](/integrate/frameworks/standalone)）。
- **检查接入。**没有日志出现时运行 `evlog doctor`，并使用 [`evlog map`](/cli/map) 找出仍未发出事件的处理器。

  ::code-group{sync="package-manager"}

  ```bash [pnpm]
  pnpm evlog doctor
  ```

  ```bash [npm]
  npx evlog doctor
  ```
  ```bash [yarn]

  ```

## 常见问题

::accordion{type="single"}
  ::accordion-item{label="How is this different from pino or winston?"}
  Pino 和 winston 每次调用都会写入一条记录。evlog 的请求 logger 会在请求过程中收集字段，并在最后写入一个包含结果、错误和耗时的事件。它还内置结构化错误、采样、脱敏和 drain。[Pino](/compare/pino)、[Winston](/compare/winston) 以及[所有日志器](/reference/vs-other-loggers)的对比页面会详细介绍差异。
  ::
  ::accordion-item{label="它会拖慢我的应用吗？"}
  一个请求只构建一个内存对象并序列化一次，而不是写入多条记录。事件发出后 drain 才运行，[管道](/extend/drain-pipeline)会批处理网络发送。成本仍取决于你记录的内容和发送位置，因此请测量自己的配置：[性能](/reference/performance)列出了基准测试及运行方式，[采样](/learn/sampling)可以减少数量。
  ::
  ::accordion-item{label="迁移期间可以保留 console.log 吗？"}
  可以。evlog 不会替换或修改 `console`，现有调用会继续工作。可以一次迁移一个路由到请求 logger，准备好后再用全局 `log` API 替换一次性消息（[简单日志](/learn/simple-logging)）。
  ::
  ::accordion-item{label="如何避免记录密钥或个人数据？"}
  首先不要把它们放进上下文：记录 ID，而不是整个对象。生产环境默认启用脱敏并遮盖常见敏感值；在 `evlog.config.ts` 中添加自己的路径和模式（[脱敏](/learn/redaction)）。
  ::
  ::accordion-item{label="它支持无服务器函数和边缘环境吗？"}
  支持。函数返回前要等待交付完成：在 Cloudflare Workers 中向 logger 传入 `waitUntil`，在短生命周期进程中对管道 drain 调用 `flush()`。参见 [AWS Lambda](/integrate/frameworks/aws-lambda)、[Cloudflare Workers](/integrate/frameworks/cloudflare-workers) 和[独立 TypeScript](/integrate/frameworks/standalone)。
  ::
  ::accordion-item{label="它支持 OpenTelemetry 吗？"}
  支持。[OTLP 适配器](/integrate/adapters/hybrid/otlp)可以将事件导出到任意 OpenTelemetry Collector 或后端，你也可以将活动 span 的 `traceId` 和 `spanId` 添加到事件中。[evlog 与 OpenTelemetry](/compare/opentelemetry)介绍了设置方法。
  ::
  ::accordion-item{label="如何关联多个服务之间的日志？"}
  每个请求事件都有 `requestId`。Hono、Express、Fastify 和 NestJS 集成会在收到 `x-request-id` 标头时复用它，因此转发该标头即可关联服务之间的事件。对于分布式追踪，`createTraceContextEnricher()` 会将收到的 `traceparent` 添加到每个事件（[Enricher](/use-cases/enrichers)）。
  ::
::

为了让各处理器中的字段名称保持一致，请继续阅读[类型化字段](/learn/typed-fields)。框架的完整选项请参见[框架指南](/integrate/frameworks/overview)。
