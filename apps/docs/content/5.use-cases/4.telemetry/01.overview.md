`@evlog/telemetry` 将 [evlog](https://evlog.dev) 的宽事件模型带给运行在他人机器上的工具——CLI、GitHub Actions、开发脚本和 CI 作业。其理念与 HTTP 日志记录相同：**一次命令执行 → 一个结构化事件**，而不是一串分析调用。

::code-group
```bash [pnpm]
pnpm add @evlog/telemetry
```
```bash [bun]
bun add @evlog/telemetry
```
```bash [yarn]
yarn add @evlog/telemetry
```
```bash [npm]
npm install @evlog/telemetry
```
::

你会自动获得命令名、经过清理的标志、持续时间和结果。只有当你有额外计数器时才调用 `telemetry.set()`——默认是数字和布尔值。原始 `argv` 从不读取；披露内容会根据你的运行时配置生成，因此它不可能与你实际收集的内容不一致。

使用 @evlog/telemetry 为我的 CLI、脚本或 GitHub Action 添加尊重隐私的遥测。

- 检测我的入口点：citty CLI（`withTelemetry`）、独立脚本（`createTelemetry`）或 GitHub Actions（`createGitHubActionsTelemetry`）
- 安装：`pnpm add @evlog/telemetry`（或 npm/yarn/bun）
- Citty：在 `src/index.ts` 中使用 `withTelemetry()` 包装根命令，并添加 `defineTelemetryCommands({ name: TOOL })`
- 脚本 / 迁移工具：使用 `createTelemetry({ name, version })`，并使用 `t.run('command', fn)` 包装每个逻辑单元
- GitHub Actions：`createGitHubActionsTelemetry()`——只有 `GITHUB_ACTION` / `GITHUB_EVENT_NAME` 会被注入 `custom`
- 对于除 `"<set>"` 标记之外所需的任何字符串值，声明 `collect.flags` / `collect.fields`
- 使用 `telemetry.set()` 将你的产品架构放入 `custom`——参见[扩展架构](/use-cases/telemetry/reference#extending-the-schema)
- 在处理程序或辅助函数中、同一异步调用栈内，为业务计数器（数字/布尔值）调用 `telemetry.set()`
- 运行 `generateDisclosure()`，并将 `TELEMETRY.md` 与工具放在一起提交
- 在 `endpoint`（或 `EVLOG_TELEMETRY_ENDPOINT`）中内置接收 URL——本地 outbox 是缓冲区，而不是目标地址
- 在我的应用中提供 `POST /api/telemetry/ingest`：使用 `@evlog/telemetry/ingest` 中的 `parseIngestBody()`，并配置 `allowedTools` + `allowedCustomKeys`，根据 `idempotencyKey` 去重，成功时返回 204

文档：https://www.evlog.dev/use-cases/telemetry/overview

::

## 从 CLI 到你的后端

磁盘 outbox（`~/.config/{toolName}/telemetry/outbox.ndjson`）是一个**可靠性缓冲区**，而不是遥测长期存放的位置。每次运行都会在本地追加一条事件，然后 HTTP drain 会将积压数据 POST 到**你的**采集端点。生命周期很短的 CI 作业和离线机器会在下次调用时继续排空。

1. **运行** — `my-tool doctor` 在用户的机器上执行
2. **捕获** — `@evlog/telemetry` 会清理 flags、检查同意，并记录一个 `RunEvent`
3. **缓冲** — 该事件会追加到 `~/.config/{toolName}/telemetry/outbox.ndjson`
4. **发送** — 在刷新时，将 `{ events: RunEvent[] }` POST 到你的采集 URL
5. **验证** — `parseIngestBody()` 允许列出 tools 和自定义 keys（[Ingest](/use-cases/telemetry/ingest)）
6. **存储** — 基于 `idempotencyKey` 去重，然后进入数据库 / 数仓 / evlog drain
7. **确认** — 在 `2xx` 时，已送达的 keys 会从 outbox 中移除

```text
CLI → @evlog/telemetry → outbox.ndjson → POST /ingest → validate → store
```

在你配置端点并且服务器返回成功状态之前，不会发送任何内容。在此之前，事件会保留在 outbox 中（或者在选择退出时被清除）。

## 为什么安装它

你可以自己搭建匿名使用遥测——出站文件、同意标志、标志清理、披露 markdown、摄取校验、首次运行提示。或者你只需添加一个依赖，就能直接获得内置的 evlog 使用方案。

### 约 28 KB 你能得到什么

| | |
| --- | --- |
| **发布体积** | ~28 KB ESM（`@evlog/telemetry`），~8.6 KB gzip —— 独立运行，不依赖 `evlog` 核心 |
| **仅服务器摄取** | `@evlog/telemetry/ingest` ~5 KB（~1.7 KB gzip）——在不把 citty 绑定引入你的 API 的情况下使用 `parseIngestBody()` |
| **运行时依赖** | 仅 `citty` + `std-env` —— 二者均为 `sideEffects: false`，可进行 ESM 树摇优化 |
| **Node** | 18+ · ESM · 包级别 `sideEffects: false` |

### 适用于代码运行的任何地方

| Surface | 入口 | 集成行数 |
| --- | --- | --- |
| **citty CLI** | 根命令上的 `withTelemetry()` | 一个包装器 + 可选的 `defineTelemetryCommands()` |
| **脚本 / 迁移器** | `createTelemetry()` + `t.run()` | 为每次逻辑运行包一层 |
| **GitHub Actions** | `createGitHubActionsTelemetry()` | 与脚本相同；自动注入 `ghaAction` / `ghaEvent` |
| **你的 API（摄取）** | 来自 `@evlog/telemetry/ingest` 的 `parseIngestBody()` | 一个校验器 + 一个 POST 路由 |

不绑定任何框架。没有 PostHog / Segment / 自定义分析 SDK。无需维护第二套 schema——披露内容直接根据 CLI 运行时使用的同一份 `collect` 配置生成。

### 你无需再构建的内容

- 隐私安全的标志采集（从不读取原始 `argv`）
- `DO_NOT_TRACK` / `EVLOG_TELEMETRY` / 带出站文件清理的持久化退出
- 带锁文件、过期锁恢复和积压清空的磁盘出站文件
- 自动生成的披露（`TELEMETRY.md` + `telemetry status`）
- 带退出提示的首次运行通知
- 带允许列表字符串字段的类型化 `telemetry.set()`
- 与 CLI 信封保持一致的服务端摄取校验
- 硬性保证：**遥测永不抛错，永不阻塞退出**

### 价值回报

一旦摄取上线，你就能回答 CLI 作者通常只能猜测的产品问题：

- 实际使用了哪些命令（`doctor` vs `sync` vs `telemetry status`）
- 运行在哪些地方失败（`outcome`、`errorCode`、版本分布）
- 操作耗时多久（每个命令的 `durationMs`）
- 还有哪些版本仍在被使用（每个事件上的 `tool.version`）
- CI 还是本地开发占主导（`env.ci`、`env.agent`、`env.tty`）

所有这些都来自每次运行的一条宽事件——就像服务器端的 evlog 一样的思路，只是不用把浏览器分析栈硬塞进终端工具里。

::callout{icon="i-lucide-package" color="neutral"}
本地试用：[`examples/telemetry-playground`](https://github.com/HugoRCD/evlog/tree/main/examples/telemetry-playground) —— `pnpm run cli -- doctor`，使用 `EVLOG_TELEMETRY_DEBUG=1` 检查负载，使用 `telemetry status` 查看披露信息。
::
