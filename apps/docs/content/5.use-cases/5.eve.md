[eve](https://eve.dev/docs/introduction) 自带可观测性：Vercel 上的 **Agent Runs**，以及通过 `agent/instrumentation.ts` 提供的可选 **OpenTelemetry** spans。`evlog/eve` 增加了第三层 —— 每次回合都可导出的 **宽事件**，其中包含你完整的 evlog 管道（drains、enrichers、尾部采样、审计）。

::callout{icon="i-lucide-info" color="info"}
eve 当前处于 beta 版本；在 GA 之前，hook 和 stream 事件的形状可能会发生变化。请在生产 agent 中固定 `eve` 和 `evlog` 的版本。

为我的 eve agent 添加 evlog 宽事件。

- 安装 evlog：pnpm add evlog
- 使用来自 'evlog/eve' 的 defineEvlogHook 创建 agent/hooks/evlog.ts
- 传入 drain、enrich 和 keep 选项（与 HTTP 中间件集成保持一致）
- 在 tools 中，从 'evlog/eve' 导入 useLogger，并在 execute() 内调用 useLogger() —— 当注册 defineEvlogHook() 时，回合 logger 会通过 AsyncLocalStorage 绑定；仅当你的运行时中 ALS 不可用时才传递 ctx
- 用户消息内容默认会被脱敏（redactMessage: true）；仅在审查过 PII 政策后才将其设为 false
- 保持 eve Agent Runs / OTel instrumentation——evlog/eve 是增量附加的

文档：https://www.evlog.dev/use-cases/eve
适配器：https://www.evlog.dev/integrate/adapters/overview

::

## 何时使用什么

| 需求 | 使用 |
| --- | --- |
| 在 Vercel 中调试会话 | eve **Agent Runs**（自动） |
| 在 Datadog / Honeycomb 中查看跨度级追踪 | eve **`agent/instrumentation.ts`** + OTel 导出器 |
| 向 Axiom / Better Stack / FS 发送宽事件，以及用于计费、审计、尾部采样 | **`evlog/eve`** |

## 快速开始

### 1. 安装

::code-group
```bash [pnpm]
pnpm add evlog eve
```
```bash [bun]
bun add evlog eve
```
```bash [yarn]
yarn add evlog eve
```
```bash [npm]
npm install evlog eve
```
::

### 2. 添加 hook

创建 `agent/hooks/evlog.ts`：

```typescript [agent/hooks/evlog.ts]
import { defineEvlogHook } from 'evlog/eve'
import { createAxiomDrain } from 'evlog/axiom'

export default defineEvlogHook({
  init: { env: { service: 'my-agent' } },
  drain: createAxiomDrain(),
  enrich: (ctx) => {
    ctx.event.region = process.env.VERCEL_REGION
  },
})
```

eve 会自动发现 `agent/hooks/` 下的 hook 文件。没有 HTTP 中间件——工作单元是一个 agent 的 **turn**，而不是一个请求。

### 3. 从工具中记录业务上下文

`defineEvlogHook()` 会在 `turn.started` 时通过 **AsyncLocalStorage** 绑定 turn logger。在工具的 `execute()` 处理器中，不带参数调用 `useLogger()`——其使用体验与 Nuxt 或 Hono 中的 `useLogger(event)` 相同。

在这个 [示例 agent](https://github.com/HugoRCD/evlog/tree/main/examples/eve) 中，支持工具会在 agent 处理退款时附加客户和订单上下文：

```typescript [agent/tools/lookup_order.ts]
import { defineTool } from 'eve/tools'
import { useLogger } from 'evlog/eve'
import { z } from 'zod'

export default defineTool({
  description: '按 ID 查找订单。',
  inputSchema: z.object({ orderId: z.string() }),
  async execute({ orderId }) {
    const order = await fetchOrder(orderId)
    const log = useLogger()
    log.set({ order: { id: order.id, amount: order.amount, status: order.status } })
    return order
  },
})
```

::callout{icon="i-lucide-plug" color="neutral"}
**回退方案：**如果在 turn 之外调用 `useLogger()` 会抛出错误，请传入 eve 工具的 `ctx`：`useLogger(ctx)`。这适用于分离的 hook/tool 包，或者 AsyncLocalStorage 无法传播的运行时。在标准的 eve agent 目录结构中并且已注册 `agent/hooks/evlog.ts` 的情况下，你通常不需要这样做。
::

### 4. Next.js Web 聊天（可选）

使用来自 `eve/next` 的 `withEve()` 包装 `next.config.ts`，并在你的应用中使用来自 `eve/react` 的 `useEveAgent()`。eve 会随着 `next dev` 一起启动，并在同一 origin 上代理 `/eve/v1/*`——工具调用、审批和 `ask_question` 都可直接开箱即用。参见这个 [示例 agent](https://github.com/HugoRCD/evlog/tree/main/examples/eve)。

## 宽事件形态

每个已完成的轮次都会发出一个事件：

```json [宽事件 — 轮次等待审批]
{
  "method": "EVE",
  "path": "/sessions/sess_abc/turns/turn_0",
  "status": 200,
  "duration": "7.9s",
  "durationMs": 7903,
  "service": "clearbill-support-agent",
  "eve": {
    "sessionId": "sess_abc",
    "turnId": "turn_0",
    "turnSequence": 0,
    "phase": "awaiting-approval",
    "sessionTurns": 1
  },
  "customer": { "slug": "acme-corp", "plan": "enterprise" },
  "order": { "id": "4821", "amount": 890, "currency": "USD" },
  "approval": { "status": "pending", "tool": "issue_refund" },
  "ai": {
    "calls": 2,
    "steps": 2,
    "inputTokens": 11724,
    "outputTokens": 282,
    "finishReason": "tool-calls",
    "tools": [
      { "name": "lookup_customer", "durationMs": 26, "success": true },
      { "name": "lookup_order", "durationMs": 13, "success": true }
    ]
  }
}
```

在审批通过后，下一个轮次会携带结果：

```json [宽事件 — 退款已完成]
{
  "path": "/sessions/sess_abc/turns/turn_1",
  "eve": {
    "sessionId": "sess_abc",
    "turnId": "turn_1",
    "turnSequence": 1,
    "sessionTurns": 2
  },
  "refund": { "orderId": "4821", "amount": 890, "status": "refunded" },
  "audit": { "action": "refund.issued", "target": { "type": "order", "id": "4821" } },
  "approval": { "status": "approved", "tool": "issue_refund" },
  "ai": {
    "tools": [{ "name": "issue_refund", "durationMs": 993, "success": true }],
    "finishReason": "stop"
  }
}
```

Token 使用量和工具执行情况会从 eve 流事件（`step.completed`、`actions.requested`、`action.result`）中累积而来。通过 `useLogger()` 设置的业务字段会在同一会话的各个轮次间沿用。在分析中使用 `eve.sessionId` + `eve.turnSequence` 来关联轮次——每个事件都保持自包含。`eve.phase` 仅用于非例行结束情况（`awaiting-approval`、`rejected`、`failed`）。

## 生产环境

长时间运行的 eve agent 应关闭终端美化打印，并使用非阻塞的 drain：

```typescript [agent/hooks/evlog.ts]
import { defineEvlogHook } from 'evlog/eve'
import { createAxiomDrain } from 'evlog/axiom'
import { createDrainPipeline } from 'evlog/pipeline'

const drain = createDrainPipeline({ batch: { size: 50, intervalMs: 5000 } })(
  createAxiomDrain(),
)

export default defineEvlogHook({
  init: {
    env: { service: 'my-agent', environment: 'production' },
    pretty: false,
    sampling: { rates: { info: 10 } },
  },
  drain,
  maxSessions: 256,
})
```

| 关注点 | 建议 |
| --- | --- |
| 终端输出 | `init.pretty: false` — 美化打印仅适用于本地开发 |
| Drain 延迟 | 批处理或异步 HTTP drains；绝不要因为 I/O 阻塞 turn |
| Head 采样 | `init.sampling.rates` — eve 每个 turn 只发出一个事件，而不是每个 token |
| 内存 | `maxSessions`（默认 `256`）会驱逐最久未使用的空闲会话状态 |
| 负载 | Hook 处理器对每个流事件的复杂度为 O(1)；成本主要取决于你的 drain |

## 选项

| 选项 | 描述 |
| --- | --- |
| `init` | 在首次 hook 调用时传递给 `initLogger()` |
| `drain` / `enrich` / `keep` / `plugins` | 与 HTTP 集成相同（[plugins](/extend/plugins)） |
| `redactMessage` | 默认 `true` — 从宽事件中省略用户消息文本 |
| `cost` / `model` | 可选的令牌定价（来自 `evlog/ai` 的 `ModelCost`）→ `ai.estimatedCost` |
| `maxSessions` | 用于上下文传递的内存会话上限（默认 `256`） |
| `include` / `exclude` | 作用于 turn 路径的路由样式过滤器（`/sessions/*/turns/*`） |

## 尾部采样

使用 `keep` 强制保留带有失败工具或高 token 使用量的轮次：

```typescript [agent/hooks/evlog.ts]
export default defineEvlogHook({
  drain: createAxiomDrain(),
  keep: (ctx) => {
    const ai = ctx.context.ai as {
      inputTokens?: number
      outputTokens?: number
      tools?: Array<{ success: boolean }>
    } | undefined
    const totalTokens = (ai?.inputTokens ?? 0) + (ai?.outputTokens ?? 0)
    if (totalTokens > 10_000) ctx.shouldKeep = true
    if (ai?.tools?.some(t => !t.success)) ctx.shouldKeep = true
  },
})
```

## 审计日志

结合 [审计日志](/use-cases/audit/overview)：通过 `init.plugins` 或全局插件注册 `auditEnricher()`，并在人类审批门触发时在工具内调用 `log.audit()`。工具拒绝会在 `action.result` 中显示，`status: "rejected"`。

## 本地运行

```bash
git clone https://github.com/HugoRCD/evlog
cd evlog
pnpm install
pnpm example eve
```

`examples/eve` 项目是一个**客服退款助手**（Clearbill SaaS）：查询客户 → 查询订单 → 发起退款，当金额超过 100 美元时需要 eve 审批。运行 `pnpm example eve`，打开 **http://localhost:3000**，然后点击一个起始提示。
