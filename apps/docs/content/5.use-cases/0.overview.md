用例是**配方**，而不是功能。每个用例都使用你已经了解的相同 evlog 基础构件解决一个具体问题：宽事件、结构化错误、drain、enricher。它们作为独立章节存在，是因为每个用例都有足够的内容规模（每个包含多个页面和专门的示例），值得直接导航，但它们不是独立的运行时：使用相同的 logger、相同的 drain pipeline、相同的类型。

| 你想要…… | 查看 |
| --- | --- |
| 将浏览器日志通过批处理、重试和 `sendBeacon` 回退发送到你的服务器 | [客户端日志](/use-cases/client-logging) |
| 捕获每次 AI SDK 调用，包括 token 使用量、工具调用、流式指标和成本 | [AI SDK](/use-cases/ai-sdk/overview) |
| 在每个宽事件中标识经过身份验证的用户（以及其组织 / 角色） | [Better Auth](/use-cases/better-auth/overview) |
| 使用哈希链、拒绝记录和支持脱敏的差异构建防篡改审计轨迹 | [审计日志](/use-cases/audit/overview) |
| 使用每次运行一个宽事件、同意和披露来为 CLI 和自动化添加埋点 | [Telemetry](/use-cases/telemetry/overview) |
| 从 [eve](https://eve.dev) agent 回合中导出宽事件（token、工具、drain） | [eve](/use-cases/eve) |
| 为每个事件添加派生上下文（User-Agent、地理位置、请求大小、trace context） | [Enrichers](/use-cases/enrichers) |

## 它们之间的关系

```text
your app code
     │
     ▼
┌──────────────────────────────────────────────────────────────────┐
│   evlog logger                                                   │
│                                                                  │
│   ┌─────────────────┐   ┌─────────────────┐   ┌──────────────┐   │
│   │ Client logs     │   │ AI SDK wrapper  │   │ Audit logger │   │
│   │ (browser → API) │   │ (token / tools) │   │ (hash chain) │   │
│   └─────────────────┘   └─────────────────┘   └──────────────┘   │
│            │                     │                    │          │
│            └─────────────────────┼────────────────────┘          │
│                                  ▼                               │
│                       enrich  →  drain                           │
│                       (User-Agent, geo, trace, …)                │
└──────────────────────────────────────────────────────────────────┘
```

每个用例都需要选择启用。可以采用一个、两个或全部五个。它们共存于同一个 logger、同一个 drain pipeline 和同一个 enrich 链中。
