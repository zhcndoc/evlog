evlog 为每一个主要的 TypeScript 框架提供集成。`log.set()`、`createError()` 和 `parseError()` 在所有框架中的行为都相同，因此下表展示的是设置步骤，而不是功能集。

::callout{icon="i-lucide-globe" color="neutral"}
没有 HTTP 框架？对于脚本、库和 worker，请使用 [Standalone TypeScript](/integrate/frameworks/standalone)；在边缘环境中请使用 [Cloudflare Workers](/integrate/frameworks/cloudflare-workers)。
::

## 不同框架之间的差异

每个框架有两点不同：如何启动 evlog，以及处理器如何获取请求日志器。

### 启动 evlog

| 模式 | 框架 |
|---------|------------|
| `evlog(options)` 中间件 / 插件 | Hono、Express、Fastify、Elysia、SvelteKit、React Router |
| `createEvlog(options)` 工厂 | Next.js |
| `EvlogModule.forRoot()` | NestJS |
| 模块默认导出 | Nuxt、Nitro v2/v3 |
| 手动工厂 | Cloudflare Workers（`createWorkersLogger`）、Standalone、AWS Lambda、Astro |

### 从处理器中获取日志器

| 模式 | 框架 |
|---------|------------|
| `useLogger(event)` | Nuxt、Nitro |
| `useLogger()` | Next.js、NestJS、Express、Fastify、Elysia、SvelteKit、React Router、Hono |
| `c.get('log')` | Hono |
| `req.log` | Express |
| `request.log` | Fastify |
| `event.locals.log` | SvelteKit |
| `context.get(loggerContext)` | React Router |
| `createRequestLogger()` / `createLogger()` | Standalone、Workers、手动设置 |

::callout{icon="i-lucide-info" color="info"}
在 Hono 中，请在处理器内部使用 `c.get('log')`，并在下层使用来自 `evlog/hono` 的 `useLogger()`。请参阅 [Hono 集成](/integrate/frameworks/hono)。
::

## 在构建时移除客户端日志

对于任何基于 Vite 的项目，[`evlog/vite` 插件](/reference/vite-plugin) 都会添加构建时优化：

- **自动初始化**：无需手动调用 `initLogger()`
- **调试剥离**：生产环境中自动移除 `log.debug()`
- **源码位置**：在日志调用中注入 `__source: 'file:line'`

它适用于 SvelteKit、通过 vite-node 使用的 Hono，以及任何由 Vite 驱动的设置。在 Nuxt 中，同样的三个选项位于 `evlog/nuxt` 模块中，因此无需手动添加该插件。
