evlog 从应用根目录的 `evlog.config.ts` 读取选项。同一个文件同时驱动服务端和 [CLI](/cli/config)。

## 配置文件

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

export default defineEvlog({
  service: 'my-api',
  sampling: { rates: { info: 10 }, keep: [{ status: 400 }] },
  drain: createAxiomDrain(),
})
```

`npx evlog init` 会为你写入这个文件。

evlog 会从应用目录开始向上查找 `evlog.config.ts`、`.mts`、`.js` 或 `.mjs`，直到工作区根目录。离应用最近的文件优先，因此单仓库根目录的一个文件可以覆盖所有没有单独配置的应用。

## 加载配置

Nuxt、Nitro 和 TanStack Start 会自动加载该文件。其他框架需要导入它：

```typescript [src/index.ts]
import { initLogger, toLoggerConfig, toMiddlewareOptions } from 'evlog'
import { evlog } from 'evlog/hono'
import config from '../evlog.config'

initLogger(toLoggerConfig(config))
app.use(evlog(toMiddlewareOptions(config)))
```

`toLoggerConfig` 传递日志器选项，`toMiddlewareOptions` 传递请求选项。每个[框架页面](/integrate/frameworks/overview)都展示准确的代码行。

## 优先级

配置文件先应用，然后由你传给框架的选项覆盖它。

在 Nuxt 和 Nitro 中，覆盖项会按键与配置文件合并。文件中的 `drain`、`enrich` 和 `keep` 永远不会被覆盖：它们会与 `evlog:*` hook 一起运行，因此事件会到达两边。在其他框架中，和配置文件一起传入的字段（例如 `evlog({ ...toMiddlewareOptions(config), exclude: ['/health'] })`）会替换对应字段，而不是合并。

## 选项

| 选项 | 类型 | 默认值 | 描述 |
|---|---|---|---|
| `service` | `string` | `SERVICE_NAME` 或 `'app'` | 每个事件上的服务名称 |
| `environment` | `string` | `NODE_ENV` 或 `'development'` | 环境名称 |
| `enabled` | `boolean` | `true` | 为 `false` 时所有调用都变为空操作 |
| `pretty` | `boolean` | 开发环境中为 `true` | 输出树形格式而非 JSON |
| `silent` | `boolean` | `false` | 不输出到控制台，但事件仍会到达 drain |
| `stringify` | `boolean` | `true` | 关闭 `pretty` 时输出 JSON 字符串 |
| `minLevel` | `LogLevel` | `'debug'` | `log` API 的最低级别。请求事件使用 `sampling` |
| `sampling` | `SamplingConfig` | - | 头部速率和尾部 `keep` 规则。参见[采样](/learn/sampling) |
| `redact` | `boolean \| RedactConfig` | 生产环境中为 `true` | 参见[脱敏](/learn/redaction) |
| `drain` | `(ctx) => void` | - | 事件的去向。参见[适配器](/integrate/adapters/overview) |
| `plugins` | `EvlogPlugin[]` | - | 参见[插件](/extend/plugins) |
| `include` / `exclude` | `string[]` | - | 要记录或跳过的路由 glob |
| `routes` | `Record<string, { service }>` | - | 按路由设置服务名称 |
| `enrich` | `(ctx) => void` | - | 在 drain 前添加字段 |
| `keep` | `(ctx) => void` | - | 自定义尾部采样 |
| `dev` | `'evlog' \| 'nitro' \| 'both' \| object` | `'evlog'` | 开发终端输出。参见[结构化错误](/learn/structured-errors#development-terminal-output) |
| `extends` | `EvlogConfig` | - | 基于共享预设构建。参见[共享设置](/cli/config#share-settings-with-extends) |
| `map`, `logs` | - | - | 仅供 CLI 使用。参见 [`evlog config`](/cli/config) |

Nuxt 还会在 `nuxt.config.ts` 中读取 `console` 和 `transport`。参见 [Nuxt](/integrate/frameworks/nuxt)。

## 脚本中的内联配置

对于小型独立脚本，直接在启动日志器的文件中向 `initLogger` 传入选项即可：

```typescript [scripts/sync.ts]
import { initLogger } from 'evlog'

initLogger({ env: { service: 'sync-job' } })
```
