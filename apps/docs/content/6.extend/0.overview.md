evlog 的设计使其两端都可以扩展——你可以**观察**通过管道的内容（而不改变管道），**接入**管道（丰富数据、决定保留哪些内容、响应生命周期事件），或者**构建你自己的组件**（用于不受支持目标的自定义排出器、自定义框架集成）。本节中的每个页面都提供了一个 `::prompt` 代码块，你可以将其放入 Cursor / Claude，以便在自己的应用中搭建该集成。

## 心智模型

```text
     应用代码
        │
        │  发出
        ▼
┌──────────────────────────────────────────────────────────────────┐
│   evlog 管道                                                     │
│                                                                  │
│   请求生命周期  →  增强  →  尾部采样  →  排出                    │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
     │                                                  │
     │  观察（不修改）                                  │  发送
     ▼                                                  ▼
┌─────────────────────────────────────────┐    ┌─────────────────────┐
│   流（进程内 + SSE 桥接）                │    │   自定义排出器       │
│   fs 读取器（NDJSON 历史记录）           │    │   排出管道           │
│   诊断通道（evlog.event）                │    │   （批处理 + 扇出）  │
│   消费者方案（开发者工具、仪表板）       │    │                     │
└─────────────────────────────────────────┘    └─────────────────────┘
```

## 三种扩展方式

### 观察管道（不改变内容）

订阅事件，而不改变发出的内容。流是实时数据源，fs reader 是历史日志，诊断通道允许消费者仅通过通道名称进行订阅，而消费者示例则展示如何将其中任意一种连接到开发工具、仪表板、CLI tail，或 `curl` + `jq`。

| 你想要…… | 使用 |
| --- | --- |
| 订阅实时事件（进程内，或通过 SSE 供浏览器 / CLI 使用） | [流](/extend/stream) |
| 从磁盘重放或持续读取历史事件 | [FS reader](/extend/fs-reader) |
| 构建一个小型消费者面板、开发工具，或连接到 `curl` + `jq` 的管道 | [消费者示例](/extend/consumer-recipes) |
| 让消费者无需导入 evlog 即可订阅，或访问 Cloudflare Tail Worker | [诊断通道](/extend/diagnostics-channel) |

### 接入管道

在管道的一个或多个生命周期阶段中挂钩。下面四个页面覆盖了完整的扩展面——当你只关心单一事项时选择其中一个；当你有多个需求时选择 `definePlugin`。

| 你想要…… | 使用 |
| --- | --- |
| 从一个统一的对象响应生命周期事件（多个 hooks 共享状态） | [插件](/extend/plugins) |
| 为每个事件自动添加一个派生字段 | [自定义增强器](/extend/custom-enrichers) |
| 事后决定是否保留某个事件（status、duration、自定义逻辑） | [尾部采样](/extend/tail-sampling) |
| 在接收端标识你的 evlog 流量（覆盖 `User-Agent` / `X-Evlog-Source`） | [身份标头](/extend/identity-headers) |

### 构建你自己的模块

当内置适配器或框架集成无法满足你的需求时，这个工具包允许你以相同的形态和易用性构建自己的方案。

| 你想要…… | 使用 |
| --- | --- |
| 将事件发送到没有内置适配器的后端（HTTP 或任何其他传输方式） | [自定义 drains](/extend/custom-drains) |
| 为生产环境将任意 drain 封装为 batch + retry + fanout | [Drain 管道](/extend/drain-pipeline) |
| 支持列表中没有的框架，或非 HTTP 运行时 | [自定义框架集成](/extend/custom-framework) |

## 哪些内容在哪里可用

只有 [stream](/extend/stream)（进程内总线 + SSE 桥接）是**仅限本地**的——它只存在于一个 Node / Bun / Deno 进程内，不能在无服务器平台（Vercel Functions、Cloudflare Workers、AWS Lambda）上工作。[stream 页面](/extend/stream)会详细解释这一限制。

其他所有内容——[FS 读取器](/extend/fs-reader)、[插件](/extend/plugins)、[自定义增强器](/extend/custom-enrichers)、[尾部采样](/extend/tail-sampling)、[身份标头](/extend/identity-headers)、[自定义排放器](/extend/custom-drains)、[排放管道](/extend/drain-pipeline)、[自定义框架集成](/extend/custom-framework)——都能在 evlog 运行的任何地方运行。
