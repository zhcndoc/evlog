**evlog** 是一个为你所交付一切内容而构建的现代 TypeScript 日志记录器。它通过一个 API 提供简单的结构化日志（可直接替代 `console.log`、pino 或 consola）、可在一次操作中累积上下文的广泛事件，以及解释错误为何发生的结构化错误，所有内容都通过同一条 drain 管线处理。在 CLI、库、后台任务、边缘工作器和 HTTP 处理程序中使用它，无需切换日志记录器。

灵感来自 [Boris Tane](https://x.com/boristane) 的 [Logging Sucks](https://loggingsucks.com/)。如果你想静态评估哪些入口点能够告诉你哪里出了问题，请尝试单独的 [`@evlog/cli`](/cli/overview)（`evlog map`）：启动早、无需配置、只需一条命令。

## 哲学

传统日志记录已失效。你的日志分散在数十个文件中。每个请求生成超过 10 行日志。当出现问题时，你只能通过 grep 在噪音中寻找信号。

**evlog** 采用了不同的方法：

::card-group
  :::card
  ---
  icon: i-lucide-terminal
  title: 结构化日志
  ---
  用类型化、结构化的事件替代 `console.log`，并通过 drain 管线流转。拥有与 pino 或 consola 相同的级别过滤、脱敏以及美化/JSON 输出。
  :::

  :::card
  ---
  icon: i-lucide-layers
  title: 广泛事件
  ---
  在任意工作单元（请求、脚本或任务）中累积上下文，并一次性发出。两种模式可以共存，彼此都不是对方的升级版。
  :::

  :::card
  ---
  icon: i-lucide-shield-alert
  title: 结构化错误
  ---
  解释为什么发生以及如何修复的错误。
  :::

  :::card
  ---
  icon: i-lucide-palette
  title: 对开发者友好
  ---
  开发阶段人类可读，生产环境为可解析的 JSON。
  :::
::

## 为什么选择 evlog，而不是 pino、winston 或 consola

evlog 是一个功能完整的通用日志记录器，恰好也支持广泛事件。具体来说：

- **零传递依赖**，gzip 压缩后约 6 kB。无需审计任何内容，也不会在下一个 Node LTS 版本中出现破坏性问题。在 [约 3 µs/请求](/reference/performance) 的基准测试中，在广泛事件模式下（1 个事件对应 4 行日志）比 pino 快 7.7 倍，并且在其他所有路径上都具有竞争力。
- **在每种上下文中使用相同的 API**：脚本、框架、边缘运行时、浏览器、库代码。不需要在 `pino-http` 和 `pino` 之间进行拆分，也不需要针对每种环境分别配置 consola reporters。
- **内置带有 `why` / `fix` / `link` 的结构化错误**：你的错误提示终于能告诉用户哪里出了问题以及该怎么做，而值班人员也不再需要逆向分析堆栈跟踪。
- **广泛事件提供免费升级路径**：当你需要关联一次操作中的上下文时，同一个日志记录器会提供 `log.set` + `log.emit`，而不是事后再拼接日志行。

请查看完整的 [功能对比](/reference/vs-other-loggers)（对等矩阵、诚实的差距和迁移片段），与 pino、winston 和 consola 逐项比较。

## 选择三种日志记录方式之一

evlog 为不同上下文提供三种 API。你可以在同一个项目中使用所有三种方式。

### 简单日志

即发即忘的结构化日志。替换 `console.log`、consola 或 pino：

```typescript [src/index.ts]
import { log } from 'evlog'

log.info('auth', '用户已登录')
log.error({ action: 'payment', error: 'card_declined', userId: 42 })
```

### 广泛事件

在任意操作过程中逐步累积上下文，然后发出一个全面的事件：

::code-group
```typescript [scripts/sync-job.ts]
import { createLogger } from 'evlog'

const log = createLogger({ jobId: 'sync-001', queue: 'emails' })
log.set({ batch: { size: 50, processed: 50 } })
log.emit()
```
```typescript [src/worker.ts]
import { createRequestLogger } from 'evlog'

const log = createRequestLogger({ method: 'POST', path: '/api/checkout' })
log.set({ user: { id: 1, plan: 'pro' } })
log.emit()
```
```typescript [server/api/checkout.post.ts]
import { useLogger } from 'evlog'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  log.set({ user: { id: 1, plan: 'pro' } })
  return { success: true }
  // 在响应结束时自动发出
})
```
::

一个日志，包含所有上下文。理解发生的一切所需的一切都包含其中。

### 结构化错误

带有可操作上下文的错误：`why` 它发生，如何 `fix`，以及指向文档的 `link`：

::code-group
```typescript [server/api/checkout.post.ts]
import { createError } from 'evlog'

throw createError({
  message: 'Payment failed',
  status: 402,
  why: '卡被发卡行拒绝（余额不足）',
  fix: '尝试其他支付方式或联系你的银行',
  link: 'https://docs.example.com/payments/declined',
})
```
```json [响应]
{
  "statusCode": 402,
  "message": "Payment failed",
  "data": {
    "why": "卡被发卡行拒绝（余额不足）",
    "fix": "尝试其他支付方式或联系你的银行",
    "link": "https://docs.example.com/payments/declined"
  }
}
```
::

## 为什么一个事件胜过十行日志

我们正在进入一个 AI 代理构建、调试和维护应用程序的时代。这些代理需要 **结构化上下文** 才能有效工作：

- **`why`**：根本原因，让代理理解哪里出了问题
- **`fix`**：可操作的解决方案，供代理建议或应用
- **`link`**：复杂问题的文档

传统的 `console.log` 和通用的 `throw new Error()` 无法提供可操作的上下文。evlog 的结构化输出旨在供人类和 AI 解析并采取行动。
