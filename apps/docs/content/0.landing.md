#headline
FAQ
#title
安装之前
#body
  ::accordion{type="single"}
    ::accordion-item{label="我已经在使用 pino 了。到底会有什么变化？"}
    你能从一次请求中了解到多少信息。pino 每次调用都会写入一行日志，因此错误到达你这里时只是一行孤立的记录，你必须在查询时通过请求 ID 将它与其余内容重新关联起来。evlog 会随着请求的执行，使用 `log.set()` 累积上下文，并在请求结束时**只发出一个事件**，将用户、路由、标志、结果和错误统一携带。错误本身也是如此：`createError()` 会附加 `why` 和 `fix`，而[目录](/learn/catalogs)则会为重复出现的故障提供稳定代码。其 API 与 `console` 相似，因此迁移基本只是机械性的。请参阅[如果你已经在使用其中一种日志记录器，会有什么变化](/reference/vs-other-loggers#what-changes-if-you-already-use-one-of-them)。
    ::
    ::accordion-item{label="我的应用已经在生产环境中运行了。现在开始是不是太晚了？"}
    不晚，而且你不必猜从哪里开始。`evlog map` 会读取你的源代码，根据每个入口点在发生故障时能够提供给你的上下文进行评分，然后列出优先修复的入口点。它不需要流量、代理或部署，因此你可以在下一次事故发生之前，而不是事故处理中，获得这份清单。无论是上线第一天还是第三年，需要做的工作都是同一份清单。请参阅[如何将它添加到已经在生产环境中运行的应用](/cli/map#adding-it-to-an-app-already-in-production)。
    ::
    ::accordion-item{label="我必须改变日志的发送位置吗？"}
    不需要，你可以继续使用已经付费的平台。evlog 负责生成事件，排水管道负责发送它们：Axiom、Datadog、Sentry、Better Stack、PostHog、Loki、ClickHouse、OTLP 或文件系统。更换提供商只需替换排水管道，而不是改变架构，因为你的处理程序从未指定目标位置。如果你是在构建平台而不是购买平台，那么同一条管道也正是你接入的位置。请参阅[排水管道如何让目标位置不出现在你的代码中](/integrate/adapters/overview#send-events-without-naming-a-destination-in-your-code)。
    ::
    ::accordion-item{label="发送这些日志会让我付出更多成本吗？"}
    通常成本会更低。一次请求只产生一个事件，而不是四行日志。在[性能](/reference/performance)中的结账场景测试里，数据量**减少了 56％，事件数量减少了 75％**，因为级别、时间戳、主机和请求绑定信息不再在每一行中重复。哪一个数字会影响你的账单，取决于你的提供商：大多数提供商按摄入的 GB 收费，因此你会节省数据量；而同时按每百万条已索引事件收费的提供商，则会让事件数量的减少带来额外收益。随后，[采样](/learn/sampling)会丢弃你原本就不会读取的内容，并强制保留错误和慢速请求。请在[哪一个数字会影响你的账单](/reference/cost#which-number-moves-your-bill)中根据你自己的流量估算价格。
    ::
    ::accordion-item{label="采用它需要多少工作量？"}
    你可以一次迁移一个处理程序。`log.info()` 的行为类似于 `console.log`，因此第一次提交不会破坏任何内容。需要学习的只有两个调用：`log.set()`，它会向正在进行的事件添加上下文；以及 `createError()`，它会为错误附加 `why` 和 `fix`，而不只是提供一个裸堆栈。请参阅[第一天需要使用其中多少功能](/start/quick-start#how-much-of-this-do-you-need-on-day-one)，或者如果你想先了解整体形态再看代码，请参阅[evlog 是什么](/start/introduction)。
    ::
    ::accordion-item{label="它在运行时的成本是多少？"}
    每个请求约 **3µs**，gzip 后约 6.3 kB，并且**零运行时依赖**，因此在开始记录日志之前无需审核依赖树。它可以运行在 Node、Bun、Deno 以及包括 Cloudflare Workers 在内的边缘运行时。在宽事件模式下，它比 pino 快 7.7 倍，因为 pino 会序列化四行日志，而 evlog 只序列化一行。在无需累积上下文的即发即忘路径上，两者的差距会缩小，[一次真实请求的成本](/reference/performance#what-it-costs-on-one-real-request)会详细拆解这 3µs。
    ::
